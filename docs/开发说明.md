# 开发说明

本文件写给维护和二次开发的人：怎么搭环境、怎么运行和打包、文档和截图怎么生成、测试怎么跑，以及几个关键模块的设计。

## 1. 环境

| 依赖 | 版本 | 说明 |
|---|---|---|
| Windows | 10 1809+ / 11，x64 | 程序只支持 Windows（用到了 Job Object、防休眠、低优先级等系统接口） |
| Python | 3.12 | 依赖见仓库根目录 `requirements.txt` |
| FFmpeg | 8.x，gpl-shared 版 | 推荐 [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds/releases) 的 `ffmpeg-n8.1-latest-win64-gpl-shared-8.1.zip` |
| Inno Setup | 6.x | 只在生成安装包时需要 |
| Node.js | 18+ | 只在生成 Word 文档时需要；导出 PDF 校对还需要 Microsoft Word |

```bat
py -3.12 -m venv _deps\venv
_deps\venv\Scripts\python.exe -m pip install -r requirements.txt
```

FFmpeg：解压后把 `bin\` 下的全部文件（ffmpeg.exe、ffprobe.exe、ffplay.exe 和 dll）以及 `LICENSE.txt` 复制到 `_deps\ffmpeg\`。
程序按以下顺序查找 ffmpeg：设置里指定的目录 → 环境变量 `BM_FFMPEG_DIR` → 程序目录下的 `ffmpeg\` → 开发态的 `_deps\ffmpeg\` → PATH。

`_deps\`、`_work\`、`build\`、`dist\`、`交付\` 都是本地目录，不进仓库。

## 3. 运行

```bat
_deps\venv\Scripts\python.exe src\main.py
_deps\venv\Scripts\python.exe src\main.py --selftest      命令行环境自检，结果写入数据目录的 selftest.txt
```

用户数据（设置、方案、模板、我的贴纸、任务记录、缓存）：打包后在 `%APPDATA%\BatchVideoMixer`；开发态在 `_work\data`。
打包后的程序旁边有 `data` 文件夹或 `portable.flag` 时，数据跟着程序走（兼容 v1.0 绿色版）。

## 4. 打包

```bat
_deps\venv\Scripts\python.exe tools\build.py --package
```

请在仓库根目录运行（在 dist 目录里运行会锁住文件夹导致打包失败）。流程：

1. 生成 `交付\使用文档.html`（`tools\make_doc.py`），PyInstaller 打包成文件夹版，复制 FFmpeg、文档、第三方授权说明，去掉用不到的 Qt 组件。
2. **安装包**：Inno Setup 编译 `tools\installer.iss` → `交付\批量视频混剪工具_安装包_v<版本>.exe`。默认装到当前用户目录，不需要管理员权限。
   ISCC.exe 依次在 `_deps\innosetup\`、`Program Files (x86)\Inno Setup 6\`、PATH 里找。
3. **单文件免安装版**：程序文件夹压成 zip，作为资源嵌进 C# 启动器，用 Windows 自带的 .NET Framework 4.x `csc.exe` 编译
   → `交付\批量视频混剪工具_免安装版_v<版本>.exe`。首次运行解压到 `%LOCALAPPDATA%\BatchVideoMixer\app\<版本>`，之后秒开；
   内容有变化（zip 的 SHA1 不同）时自动重新解压，并清理旧版本。

加 `--zip` 另外生成绿色版压缩包。版本号在 `src\mixer\__init__.py`（安装包和启动器的版本信息都从这里取）。

发布到 GitHub Releases 时文件名用英文（GitHub 会改掉中文文件名）：

```bat
gh release create v1.1.0 BatchVideoMixer-Setup-v1.1.0.exe#安装包（推荐） BatchVideoMixer-Portable-v1.1.0.exe#免安装版（单文件） ^
  --title "v1.1.0" --notes-file 发布说明.md
```

## 5. 文档

`docs\使用文档.md`、`docs\上手文档.md` 是唯一的来源，HTML 和 Word 都由它们生成：

```bat
_deps\venv\Scripts\python.exe tools\make_doc.py                 → 交付\使用文档.html
cd tools\docx
npm ci
node make_manual.js                                             → 交付\使用文档.docx
node make_quickstart.js                                         → 交付\上手文档.docx
powershell -ExecutionPolicy Bypass -File finalize.ps1 -docx <docx 绝对路径> -pdf <pdf 绝对路径>
```

`finalize.ps1` 用 Word 更新目录页码并导出 PDF，`contact.py` 把 PDF 拼成缩略图方便检查版面。
Markdown 里给 Word 用的写法（GitHub 上不显示）：图片行尾 `<!-- w=520 -->` 指定宽度，`<!-- pagebreak -->` 让下一章换页；
GitHub 提示框 `> [!TIP]` 在 Word 里是蓝色提示框。

截图（离屏渲染，不弹窗口）：

```bat

_deps\venv\Scripts\python.exe -X utf8 tests\doc_shots.py              使用文档截图 → _work\docshots
_deps\venv\Scripts\python.exe -X utf8 tests\doc_shots_quickstart.py   上手文档截图 + 标注坐标 → _work\docshots_quickstart
```

## 7. 关键设计

**两阶段渲染**（`render.py`）：每个片段单独一条 ffmpeg 渲染成 MOV（精确 seek、去水印、画布适配、变速、统一帧率和帧数，音频统一 48k PCM），
有叠化转场的边界额外渲染“衔接片”；再用 concat 顺序合成，最终一次编码完成滤镜、贴纸、文字、混音、响度统一。
相比单条 filter_complex（30 段时内存 4.6GB），峰值约 0.7GB，片段可并行、可缓存。

**音画同步**（`render.py`）：输入跳转（-ss）后画面和声音共用同一个时间零点，片段渲染时**不能各自把起点归零**（PTS-STARTPTS），否则素材里声音比画面晚开始的时间差会丢掉。画面用 `fps=…:start_time=0`（晚开始时补第一帧），声音用 `aresample=async=1:min_hard_comp=0.1:first_pts=0`（晚开始 / 中途断档补静音），之后按帧数、采样数精确截取，拼接时不累积误差。

**整段拼接**（`planner.py` `_plan_whole_mode`、`render.py` `_hold_parts`）：素材完整使用，有时长上限时只挑放得下的完整素材；转场是“定格过渡”——前一段最后一帧与后一段第一帧各复制 T 帧做 xfade，相邻素材不重叠（`PlanItem.trans_hold`），成片时长 = 素材帧数之和 + 转场帧数；查重有冲突的素材整个跳过，复查发现不同素材间重复时整段移除后重新合成。

**生成时电脑负载**（`ffmpeg.py` `PERF_MODES`、`utils.py`）：所有 ffmpeg 子进程都在同一个 Windows 作业对象里，流畅优先 / 均衡给作业对象设 CPU 总量硬上限（60% / 80%，JobObjectCpuRateControlInformation），子进程用空闲 / 低于正常优先级，并调低内存和磁盘读写优先级；并发数、片段并行数、每路线程数、最终合成线程数都按“可用 CPU”分配。

**时长上限**（`planner.py`）：每条目标时长在 `[上限×(1−浮动), 上限]` 随机，按帧累计片段（含片头片尾、扣除转场重叠），
最后一段按剩余帧截短；剩余不足一个片段且还没到下限时允许补一个不短于 0.8 秒的片段；合成时再按目标时长兜底截断。

**防重复**（`dedup.py`、`planner.py`、`batch.py`）：

1. 每 0.5 秒抽一帧，逐帧检测并裁掉黑边/模糊背景（二阶差分细节能量），算 64 位 pHash 和镜像 pHash。
2. 连续多帧（标准档 3 帧 = 1.5 秒）指纹差异 ≤ T 才算重复；同一素材内的配对要求间隔 ≥ 3 秒、不是静止画面、中间画面离开过；
   用并查集把同一画面的所有出现位置归成一个“内容编号”。
3. 规划时同一条成片里每个内容编号只用一次（片段只取不含已用画面的最长区间；整段拼接时切掉重复部分）。
4. 成片复查：对成片抽帧找相似画面作为候选，再按成片计划把每个采样点换算回“素材 + 时刻”，用查重索引或素材原始画面的指纹确认
   （画布模糊背景、贴纸标题会让不同内容“看起来像”，不能只看成片）；确认是真重复才删除后出现的那段，最多 3 轮。

**单文件版启动器**（`tools\launcher\Launcher.cs`）：互斥锁防止同时解压，先解压到临时目录再改名（中途断电不会留下半个程序），
`--selftest` / `--wait` 时等待子进程并返回退出码。
